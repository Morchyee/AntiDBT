# Core pipeline review

Verdict: changes required. Read-only implementation review of CaptionPipeline, TranslationScheduler, SubtitleStore, SubtitleProjection and all current Core test sources. Existing prototype/artifacts/core-tests.json reports 20 tests, zero failures. No unchanged tests were rerun; only this review document was written.

## Actionable findings

1. **P1 — Continuous revisions can starve incremental translation indefinitely** (`prototype/src/AntiDbt.Core/TranslationScheduler.cs:25,37`). Every revision cancels the preceding job and restarts a trailing debounce. A segment updated every 200 ms with the default 350 ms debounce never reaches TranslateAsync until silence/finalization. Even at slower update rates, cancellation of every in-flight request can prevent any translation when service latency exceeds the revision interval. This defeats incremental low-latency translation during sustained speech. Coalesce pending revisions with a bounded maximum wait and distinguish an in-flight request from the latest pending revision; retain revision/generation checks for result application. Add a sustained partial-stream test with updates faster than debounce and a deliberately slower translator, asserting bounded request progress before finalization. Existing scheduler tests use final=true and never exercise this path.

2. **P1 — Two canceled uncooperative requests can block all later translation** (`prototype/src/AntiDbt.Core/TranslationScheduler.cs:38,47-49`). TimeoutSeconds only cancels a token passed to the provider; the awaited provider task has no enforced wait deadline. A provider ignoring cancellation (already modeled by ControlledTranslator) retains a semaphore slot until it returns. After two obsolete requests hang, all fresh requests, including a new generation after CancelPending, wait indefinitely. Bound the scheduler's wait on the provider task and safely observe detached completion, with an explicit policy for limiting outstanding uncooperative work. Test two canceled never-completing requests followed by a current-generation request; the current two-request test manually completes both and misses starvation.

3. **P2 — User stop deadline cuts off the advertised final-result drain** (`prototype/src/AntiDbt.Core/CaptionPipeline.cs:90-94,138-141`). The pipeline allows four seconds to complete/read ASR and then three seconds for translation, but StopAsync cancels the lifetime after only three seconds including audio stop and backlog pacing. A cooperative ASR returning its final result at 3.5 seconds (within the internal four-second drain budget) is canceled on an ordinary user stop, and its final caption/translation is lost. Give stop a consistent total bounded budget or explicitly allocate one deadline across backlog, ASR drain and translation drain. Add a delayed-final-on-stop test rather than only instant TestAsrSession completion.

4. **P2 — Compact projection loses multi-segment sentence prefixes** (`prototype/src/AntiDbt.Core/SubtitleProjection.cs:9-15`). Reverse traversal stops on punctuation in the newest row itself. Rows `Hello` followed by `world.` therefore project as only `world.`. Conversely, a preceding `Previous sentence.` is added before the boundary check when the newest row is an unfinished next sentence. Detect boundaries between rows: include all pieces of the newest sentence and stop before the preceding completed sentence. Verify both multi-row completed and new partial sentence examples. Existing punctuation coverage checks Expanded only.

## Generation/reconnect and remaining concerns

- SubtitleStore rejects older revisions and wrong session generations under its lock. Translation completions check cancellation and exact generation/revision before applying. Reconnect advances the generation and preserves history, preventing segment-ID collisions. These are sound foundations.
- CaptionPipeline cancels the reader token in the connection finally but does not await/observe the reader there. Retry exceptions from SendAudioAsync can leave a reader task running through session disposal, and terminal drain timeout can leave its eventual exception unobserved. Consider a bounded reader join in connection cleanup; add an actual reconnect fixture (current reconnect test covers SubtitleStore only).
- Stop/Dispose and Start are not synchronized. The present tests cover single-threaded lifecycle with cooperative instant fixtures, not concurrent stop/dispose, stuck send, canceled connect, repeated reconnect or late read callbacks.
- No live ASR/translation behavior or hardware behavior was established by this review. The findings above follow concrete source paths; priority reflects functional impact rather than a claimed reproduced production incident.
