# Provider implementation review

Verdict: changes required. Reviewed current Providers source/tests, provider-tests.json, and the supplied official-contract notes in PROVIDER-SPECS.md. No cloud requests, test reruns or implementation edits. Existing results are explicitly localhost HTTP/WebSocket evidence, not authentication or model entitlement evidence.

## Actionable findings

1. **P1 — Default automatic source language becomes an undocumented MT language code** (`prototype/src/AntiDbt.Providers/VolcengineMachineTranslationProvider.cs:28`; integration: `AntiDbt.Core/SubtitleStore.cs:36`). Default ASR Language is empty; ASR emits null language, SubtitleStore converts it to `auto`, and TranslationScheduler forwards that string. The MT provider then serializes `source_language: "auto"`. The documented automatic-detection contract is omitted/empty, not the application sentinel `auto`. Normalize automatic language to omission at the provider boundary. Add a default-ASR-to-store-to-MT integration test; the existing MT test constructs an empty SourceLanguage directly and misses the actual default path. Whether the cloud happens to accept `auto` is unverified; the current request does not follow the selected documented contract.

2. **P1 — Utterance identity assumes provisional start timestamps never change** (`prototype/src/AntiDbt.Providers/VolcengineAsrProvider.cs:109-121`). The documented application policy calls for reconciling cumulative snapshots using timestamps and finalized-prefix order. Implementation instead keys every utterance solely by start_time and never reconciles/removes unmatched provisional rows. A provisional utterance at start=0 revised to start=20 becomes a second segment; a provisional utterance split/merged by the second pass also leaves obsolete source rows. Implement stable local identities for the provisional suffix against the finalized prefix, with explicit replacement/removal behavior, or reject unsupported reconciliation shapes rather than silently duplicate captions. Add shifted-start, provisional split/merge, repeated finalized-prefix and multiple-utterance snapshot fixtures. Current test only changes text/finality on one constant start=0. Real cloud frequency of these cases remains unknown; the exact-start-only assumption is not established by the supplied spec.

3. **P2 — Decoder hardcodes a one-word header despite the header-size field** (`prototype/src/AntiDbt.Providers/VolcengineAsrProvider.cs:84-88`). Requiring packet[0]==0x11 and starting payload metadata at offset=4 rejects any otherwise valid version-1 frame with an extended header. The selected contract explicitly defines low nibble as header size times four and warns against assuming fixed payload offsets. Validate version and bounded header size separately and start optional sequence parsing at that computed offset. Add an extended-header response fixture. Existing fixtures all use 0x11, so this contract branch is untested; no claim is made that current cloud responses routinely include extensions.

## Additional observations

- `VolcengineAsrProvider.cs:119` suppresses same-text/same-finality updates even if end_time changes. This leaves stale timing metadata for a growing unchanged hypothesis; include timing changes in reconciliation if latency/segment endpoints are expected to track these updates.
- The per-session `segments` dictionary retains all finalized results for the lifetime of a connection, independent of bounded UI history. Long continuous capture therefore has unbounded provider-side history. A finalized-prefix watermark/tombstone policy can preserve deduplication without retaining all transcript text indefinitely.
- Outgoing request/audio/final packets use big-endian sequences and payload lengths, with a negative final sequence and zero-length final audio frame. Incoming fragmented WebSocket messages, gzip output and HTTP responses are capped at 4 MiB. Cancellation and final drain are bounded for the cooperative network APIs used here.
- New/legacy headers and resource defaults match the selected notes. No generic AK/SK or undocumented context/messages field is sent. LiveInterpret remains gated. Production MT disables redirects; endpoint validation rejects non-loopback hosts other than the selected official host. Reviewed error paths do not echo keys or server response bodies.
- ASR protocol error packets are rejected generically before reading their code/payload, and handshake log IDs are not captured. These limit diagnostics but do not leak secrets; avoid claiming full protocol-error decoding/log-ID support.
- CompleteAsync and DisposeAsync are not independently concurrency-safe/idempotent: concurrent Complete calls can race past the initial completed check, and repeated Dispose calls cancel a disposed CTS. Current pipeline normally serializes completion, so these are secondary lifecycle hardening concerns rather than demonstrated default-path failures.

## Verification boundary

The tests meaningfully exercise localhost framing, gzip fragmentation, headers, malformed input, safe errors, cancellation and bounded drain. They do not establish mainland cloud entitlement, actual cumulative response shapes, automatic-language acceptance, or authenticated final framing behavior. Retain those as explicit live-verification gates after the actionable source issues are fixed.
