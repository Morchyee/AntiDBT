# Cloud Speech SDK delivery (review fixes included)

## Scope / APIs
New net9.0 AntiDbt.CloudSpeech project only; public AzureSpeechProvider / GoogleSpeechProvider have parameterless production constructors and injectable transport constructors. Core contracts unchanged. Root owns catalog/wiring, UI, secure storage, retry and release integration.

Azure uses official Microsoft.CognitiveServices.Speech 1.52.0: SpeechConfig.FromSubscription, SpeechRecognizer Start/StopContinuousRecognitionAsync, 16 kHz/16-bit/mono PushAudioInputStream. Recognizing/Recognized pass actual SDK fields through AzureEvents; NoMatch is ignored. Offset/duration map to audio times; local utterance IDs/revisions remain stable. Canceled maps official SDK categories to controlled messages (Authentication, RateLimited, Configuration, Timeout, Network, ModelUnavailable or Service). SessionStopped completes the result channel. EOF closes push stream and preserves late finals until stopped. NativeResources tracks each acquisition; constructor failure unwinds acquired format/push/audio/recognizer, and disposal attempts every resource even when one disposer throws. SpeechConfig is not IDisposable in installed version.

Google uses official Google.Cloud.Speech.V2 1.8.0 SpeechClient.StreamingRecognize duplex gRPC. Explicit caller service_account JSON is validated before ServiceAccountCredential.FromServiceAccountData / GoogleCredential.FromServiceAccountCredential; no ADC/file/environment discovery. token_uri must equal https://oauth2.googleapis.com/token. Region-derived official endpoints only; custom Endpoint rejected. Stable long model only, default long. Regional/script BCP47 language required, en-US default only when blank. First request contains recognizer/config, explicit Linear16 16000 Hz mono, interimResults=true; later audio <=15000 bytes. Production receive loop processes actual SDK response objects: final portions settle individually, consecutive nonfinal portions aggregate into one complete pending utterance revision. Empty alternatives ignored. RpcException categories converted without exposing status detail/body.

## Lifecycle and silence decision
Single-writer session gate, operation-linked 12s connect / 15s send / 4s EOF deadlines. A canceled acquired operation or deadline failure marks session terminal, cancels actual Google call, starts bounded exactly-once cleanup, then releases writer gate. Later sends reject EOF/terminal sessions. Failed connection releases acquired transport immediately. EOF input closure is separate from result completion, so finals after EOF drain. Google overall 4m45 timer starts before SDK startup/config transmission, conservatively including connection setup, and directly aborts the gRPC call when expiring. Disposing cancels blocked receive and send; stop/dispose work is deferred away from native event callbacks.

Removed 30-second no-result timeout: normal silence can produce no recognition responses. Read waits are bounded by the overall stream lifetime / operation cancellation / dispose instead of treating silence as network outage. All user-visible provider messages include their controlled ProviderErrorKind category. No raw SDK diagnostics are used in messages or inner exceptions.

- sdk-review-red-build.txt: actual successful serial compilation of new regression fixtures before fixes.
- sdk-review-red.txt: 11 behavioral failures before fixes: Google multi-interim and final+interims, canceled pending write and second send, connection cleanup, EOF/reject send, five SDK RpcException category cases, native disposer unwind. These supersede the initial environment-only RED log.
- sdk-review-green-build.txt: serial build succeeded, zero compiler warnings/errors; one NU1900 vulnerability-metadata network warning remains.
- sdk-review-green.txt: 36/36 offline assertions passed (original22 + regression14). Google receive fixtures use real StreamingRecognizeResponse / Result / RpcException objects through production receive loop. Blocked write fixture intentionally ignores cancellation until transport release; concurrent queued send is rejected. Late final is emitted after EOF. Azure converter tests exercise actual SDK enums/fields, NoMatch and time/category mapping; staged acquisition fixtures verify cleanup of every earlier stage and throwing disposer. Silent blocked Google receive is canceled by a shortened real-clock overall limit, not a 30-second idle policy.

All evidence is offline gateway/SDK request-response conversion and lifecycle fixture evidence. No in-process real gRPC server, actual native recognizer start, authenticated cloud call, credential/token request, region/model availability, or recognition quality verification. Native constructors/Dispose/Write are synchronous SDK calls and their actual blocking behavior cannot be guaranteed by task WaitAsync bounds; release smoke remains necessary. Test count counts assertions/cases, not cloud scenarios. Initial sdk-red.txt remains a NU1301 restore-environment failure, not behavioral proof.
